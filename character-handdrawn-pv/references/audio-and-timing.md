# 音频与时间轴

## 先识别输入

区分成曲、伴奏、干声、导唱、对白、工程文件、MIDI 与音色模型。探测真实文件格式、时长、声道和采样率；不要因为用户把 VPR/MIDI 叫“伴奏”，就把工程当成已可播放的音频。

记录各文件相对于最终音乐的时间原点。源视频、工程导出和最终混音可能有静音头或编码延迟；某个文件上的时间戳不能原样套到另一个。`1.28–1.35` 之类表示有歧义时，结合总时长核对是 1 分 28 秒到 1 分 35 秒还是小数秒。

## 按现有条件选择演唱路线

| 已有材料 | 下一步 |
| --- | --- |
| 可用成曲 | 使用并对齐；不重新生成演唱 |
| MIDI/歌声工程与歌词 | 检查音轨、速度图和音符；先短段填词与发音验证 |
| 只有参考歌和新词 | 可用音符提取或人工扒谱作起点，检查八度、连音、休止与节拍，不能直接当准确乐谱 |
| 已有合格导唱、需换声线 | 小段音色转换试验，确认语言和音域再全曲 |
| 只有歌词且无固定旋律 | 先确定原创作曲或已有旋律填词，不能假定原曲和节奏 |

工具是可替换部件。根据实际可用的合成器、声库、设备、模型和预算决定；DiffSinger、OpenUtau、商业歌声软件或 RVC 都不是所有项目的必装依赖。先检测已有环境，不覆盖用户安装或下载巨量模型来代替选型。

## 填词与音色转换的检查顺序

1. 将新词与乐句对应，核对字数、重音、换气和拖音。一字多音、衬字与停顿要明确。
2. 在一个包含高低音与关键发音的短段验证导唱，检查漏字、挤字、吞字、错误断句与拼音。改变词句后同步更新歌词、音节映射和分镜。
3. 全曲导唱检查后再换音色。音色转换不会修复跑调、节奏错误或错词；必要时回到导唱修改。
4. 保存可复现参数与模型来源说明。不要承诺完全等同某角色原声，也不要编造模型作者或许可信息。
5. 听验输出和伴奏的对应段落。波形、F0 或自动对齐能辅助定位，不能证明吐字、音质和情绪已合格。

比较付费工具或当前型号/版本时核对官方资料；不凭记忆给出现行价格或兼容结论。没有新的购买和安装需求时无需展开选型。

## 游戏对白和独白

先核实台词真的存在、确为该角色、语言正确、截取范围包含完整字句。用户未提供的真实游戏台词不能捏造为已录制素材；可以把镜头改为无声表情或暂留台词槽位。

从用户文件截取对白并保留源文件，优先使用已有干声；有背景音乐时用可用的人声分离工具提取，听验残余音乐、混响和截断音。人声分离有伪影，不能只看输出文件存在。

先放在音乐允许的位置，再用前后画面解决剧情衔接。镜头可以保留，即使原计划台词不可用；不要为了一个不存在的录音删掉已确认的叙事画面。

音量依据用户期待与实际听感。需要对白作轻声背景时，降低对白并保留音乐主体，不默认把音乐大幅压低。若用户要听清台词，再选择自动化音量、轻微压低音乐或其他混音方式。不存在适用所有素材的固定增益。

## 声音事件驱动动效

先试听相关窗口并区分轻滴水、人物扑通入水、持续水流、破水而出等事件，再设计视觉。波形峰值只能定位可能的瞬态；无法听验时请用户描述或明确标记为待确认，不把猜测写成事实。

一组声音可组成一条连续动作：冲击/入水 → 水下流动保持 → 出水/水面退去。应覆盖整段的状态变化，不是在几个峰值分别叠不相关特效。将峰值、保持区间和出水点记录在最终音乐时间轴中；替换音源后复核。

最终预览检查音乐、主唱、对白和音效的相对音量、开头偏移和结尾尾音。导出时检查混音所用文件与预览相同；不是只确认音轨存在。
